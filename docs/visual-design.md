# 記事画像の設計と検品

## アイキャッチ

記事の問いや意外性を、一つの主役と短いフックで伝える。選択したアイキャッチテンプレート画像を必ず参照し、配色・余白・文字組みなどの視覚要素を引き継ぐ。短いフックは大きく配置し、一覧とモバイル表示でも読めることを必須とする。1280×670pxのPNG、短く正確なフック、視認性を維持する。テンプレート画像がない場合は完成扱いにしない。

バッチでは生成前に親が各briefへ `visual_direction` を記録し、全記事の方向性を比較して確定する。記録するのは構図、主役、表現技法、配色、文字配置、他記事との違い。色・文言だけの変更は別デザインと数えない。各記事は他の各記事と、構図・主役・表現技法のうち少なくとも2軸を変える。記事内の本文画像には一貫した視覚言語を使ってよい。

7記事の例（固定割当ではない）：ビットコインは分散する台帳の俯瞰イラスト、税務は取引票のエディトリアルコラージュ、ウォレットは鍵と署名の断面図、ステーブルコインは準備資産と償還の循環、DeFiは流動性プールの等角図、NFT入門はトークンと画像を分けた二層構図、NFTの権利は利用許諾を切り分ける紙のレイヤー表現。

## 本文図解

各図について、読者の疑問、本文の根拠段落、図で分かる結論、登場要素、要素間の関係、必要なラベル、挿入位置、altを設計する。順序にはフロー、条件には分岐、違いには比較、所有・保存先には層や対応関係など、説明内容から形式を選ぶ。

「記録→条件→判断」のような、別記事へそのまま移せる汎用図は禁止。たとえばNFTなら、トークンID・メタデータ・画像の保存先を描き、著作権の移転が別契約であることを本文に沿って示す。矢印が送金・参照・許諾の何を表すかを明示する。装飾、章タイトルの転載、同じ図へのラベル差し替えで枚数を満たさない。

## 生成と品質確認

専任画像agentが各画像を、選択したテンプレート画像を参照する別プロンプトのimage_genで新規生成する。SVG/HTMLの描画だけで画像を代用しない。画像処理は生成済み画像のクロップ・リサイズ・正確な文字の補正に限定する。生成ツールや専任agentが使えない場合は未完了を記録し、完成・監査済みとして投稿しない。並列起動が部分成功した場合は成功したagentを回収し、終了した枠を閉じて同工程を分割する。

親は最終画像を全枚、原寸と横幅約375pxの表示で目視する。文字切れ・誤字・大きさ・コントラスト、関係の正しさ、本文との対応、装飾に埋もれていないか、テンプレート画像を参照していることを確認する。大きなHOOKが読めない画像は不合格とする。バッチは全アイキャッチを並べ、色と文字を除いても違いが分かるか確認する。代表画像だけの検品は不可。問題画像だけ最大2回再生成し、解決しなければ未完了として停止する。

## 投稿前記録

親が同名briefに `visual-review` コードブロックを1つ保存する。JSONは `{"version":1,"images":[...]}`。imagesはアイキャッチと全本文画像を過不足なく含み、各要素は以下を持つ。

- `sha256`：最終ファイルのSHA-256。変更後は再検品して更新する。
- `generator`：実際に使った `image_gen`。
- `prompt`：実際の生成プロンプト。
- `role`：`eyecatch` または `body`。
- `purpose`：記事固有の訴求、または図で解消する疑問。
- `review`：`{"fullSize":true,"mobile":true,"articleMatch":true,"notes":"実物で確認した内容"}`。

未実施をtrueと書かない。ハッシュ・記録の機械チェックは目視検品や独立監査の代わりではなく、未検品や検品後差し替えの検出用。記録だけから美しさや生成元を証明できるとは報告しない。
