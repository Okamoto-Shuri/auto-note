# 編集方針

## 既定値と質問条件

- MEDIA：時事・技術などを、専門外にも分かる落ち着いた日本語で解説するnote。
- PERSONA：テーマに関心のある一般読者。KWに合わせ状況・疑問を具体化しbriefへ記録する。
- GOAL：閲覧・スキ・フォロー獲得。記事ごとの明示指定があれば優先する。
- EEAT：本人の一次情報なし。自分の実績・体験・取材・実測として書かない。公的機関等の原資料は根拠に使用する。
- KW：依頼テーマ→state.topic_backlog先頭。どちらもなければ質問する。
- SUB_KW：KWから候補を立て、researcherの検索結果で補正する。
- INTERNAL：state.publishedのtitle/note_urlから関連候補だけ取得する。
- 固定済みの目的・文体・文字数・EEATは毎回質問しない。重要な未指定事項だけ最大7問、回答例を添えて確認する。
- 仮定と根拠はbriefへ記録する。既存記事を読んでいなければ「既存本文から推定」と書かない。

## 文体・構成

- 本文4,000〜6,000字。導入・見出し・FAQ・まとめ・CTAを含め、計数はdocs/note-format.mdに従う。
- 結論を先に示し、読者の疑問→結論→根拠→適用→次の行動の順に運ぶ。
- 各章はPREPを基本とし、手順は時系列にする。
- 一文60字以内、漢字比率30％前後を目安にし、同一文末を3回連続させない。
- 文章を詰め込まず、話題や論点が切り替わる位置で段落を分ける。1段落は2〜4文を目安とし、長い段落を連続させない。
- H2・H3の前には投稿変換時に空白段落を1つ入れ、前の本文との間に物理的な余白を作る。見出し直後は空けず、本文へ自然につなぐ。
- KW密度は指標にせず、見出し・章冒頭・まとめへ自然に配置する。体言止めの連続を避ける。
- 本論H2は5〜7本、各H3は2〜4本。FAQ・まとめのH2は別枠。本論H2へのKW使用は2本まで。
- 箇条書きは1章1箇所まで。本文で表を使わず、比較は地の文や箇条書きにする。
- 根拠のない断定・最上級・成果保証、一般的な誇大表現を禁止する。テーマ固有のNGもbriefに記録する。

## 調査・事実確認

- 検索は原則1〜2回、詳細確認は公式・公的機関・大手専門メディア等の最大3サイト程度に絞る。
- 事実と推定を分け、未取得は判定不能とする。検索順位・平均文字数も捏造しない。
- 相場・価格・政策・会合日程など変わり得る事実は毎回最新確認する。過去の値を現況として流用しない。
- 主張ごとにURL／資料名／公表日／確認日時／対象期間／単位／対象範囲／前提を必要な範囲で添える。
- 本文は主張の近くに出典リンクを置く。短期変化と長期水準、変化率と寄与度、観測と決定を区別する。
- 具体例には数値・固有名詞・条件を含める。仮定例は仮定と明記し、実測に見せない。
- 不足データは[要データ：内容]、疑義は[要確認：内容]、未確認出典は[要出典：内容]。未解消のまま投稿しない。
- 事実確認はseo-auditorへ委譲。計数スクリプトは事実・文体の判断を代替しない。

## 最終確認

- 本文画像2〜3枚は理解補助として機能する内容にし、本文との整合・文字の正確さ・可読性・構図を目視検品する。
- アイキャッチはテンプレートのデザインを保ち、文字の正確さ・可読性・構図を目視検品する。
- 本文とタイトル・FAQ・画像の整合、出典の支持範囲、監査の全指摘反映を確認する。
- SEO詳細はdraft skillのwriting.md、公開判定はpublish skillを使う。
