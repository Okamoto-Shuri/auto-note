# Phase 4〜6：執筆要件

共通文体はdocs/editorial-policy.md、保存・計測はdocs/note-format.mdに従う。

## Phase 4：タイトル・導入

- 訴求軸を分散させタイトル10案を作る。各28〜32字、KWは原則先頭15字以内に自然に配置する。
- 検索意図一致／差別化／クリック誘因／非誇大を各5点で採点し、上位3案と各選定理由1文を残す。
- メタは3案、各120〜140字。KWは先頭60字以内。「課題→解→読了後の状態」の順にする。
- メタはbriefだけに保存し、本文・frontmatterへ入れない。
- リードは最初の段落120〜160字。冒頭20字以内にKWを含め、読者の具体的状況を描く。
- 続く導入は350〜450字。疑問→結論→根拠の信頼性→得られることを示す。KWは導入内で2回まで。
- 一次情報がないため権威・実績を創作せず、公開資料の調査・整理として信頼性を示す。

## Phase 5：本文

- plannerの全体配分で書く。目安は5,200字前後とし、上限まで修正余地を残す。
- リード・導入約550字、FAQ約500字、まとめ・CTA等約300字を先に確保し、本論に残りを配分する。
- 各章に結論・理由・根拠のある具体例・読者への適用を含める。短縮時も論拠や条件を落とさない。
- 1段落2〜4文を目安に、論点や話題の切り替わりで段落を分ける。見出しを含む各ブロックの間はMarkdown上で1行空け、長い段落を連続させない。
- H2・H3の前は公開時に空白段落が入る前提で構成する。見出し直後に余分な空白を重ねず、最初の本文を続ける。
- スニペットを狙う見出し直下に40〜60字の定義文を置く。
- H4はH3内の太字小見出しへ畳み込み、見出し階層を飛ばさない。
- 箇条書きだけで章を埋めず地の文で論理を運ぶ。全章続けて執筆し、章ごとの「続けて」は求めない。
- 初稿と監査反映後に一括チェックする。事実・文体・数値条件は親も読み直す。
- 各章の実測・配分差・要データ/要確認/要出典の残数を記録し、全章完了と総字数を報告する。

## Phase 6：FAQ・画像・リンク・CTA

- 本論で扱わない周辺疑問を4〜6問、回答は各80〜120字。「よくある質問」に実装する。
- Article / HowTo / FAQPage / BreadcrumbListから適切なJSON-LDを実際に生成し、briefだけへ保存する。
- JSON-LDに本文にない事実を書かない。FAQPageなら質問・回答を本文と一致させる。
- 画像指示には位置・内容・alt・ファイル名を記録する。altは画像の説明としKWを詰め込まない。
- 必須アイキャッチの短い表示タイトル・KICKER・雰囲気・出力先をbriefへ記録する。参考HTMLは画像agentが選ぶ。
- 概念図等を設計した場合は実装または不要とした判断を記録する。必須アイキャッチは省略しない。
- plannerの内部リンクを自然な前後文とアンカーで本文へ反映する。候補がなければ無理に設置しない。
- GOALにつながる自然なCTAを中盤と末尾の2箇所へ置く。

## briefの必須記録

Phase 0の変数・質問/回答・仮定、Phase 1の全分析と出典、
Phase 2の3案採点・推奨理由・素材要否・クラスター・15語以上のエンティティ、
Phase 3の各見出しの役割・配分・狙い・画像案、Phase 4の10案採点/上位3理由/メタ3案、
Phase 5の実測、Phase 6の実装結果/画像指示/JSON-LD、
Phase 7の監査結果と反映箇所、未確定タグ、実行計測。
共通指示は複写せず、今回の分析・決定・証拠を保存する。
